第一讲：C语言程序的机器级表示

x86_64 的过程调用

过程调用的参数传递（Linux/GCC）:

  • 通过寄存器传送参数
  • 最多可有6个整型或指针型参数通过寄存器传递
  • 超过6个入口参数时，后面的通过栈来传递
  • 在栈中传递的参数若是基本类型，则都被分配8个字节
  • call（或callq）将64位返址保存在栈中之前，执行R[rsp]←R[rsp]-8
  • ret从栈中取出64位返回地址后，执行R[rsp]←R[rsp]+8

在64位寄存器中浮点数使用的寄存器和32位的不一样！ 整数使用通用寄存器，如果涉及到浮点数，那么浮点数使用XMM来传递 x86-64过程的浮点参数传递 最多可有8个浮点型参数通过XMM0~XMM7传递 超过8个浮点入口参数时，后面的通过栈来传递，各占8B 使用XMM0存放浮点数返回值 所有XMM都是调用者保存寄存器，被调用过程无须保存任何XMM寄存器即可直接使用 当入口参数列表中同时包含整型、浮点型和指针型参数时，整型和指针型参数通过通用寄存器传递，浮点型参数通过XMM寄存器传递。 每个入口参数与寄存器之间的映射关系取决于参数类型和排列顺序 如：函数原型为 double funct(int i,double x,long j,double y,double *yptr)时，
参数 i、j 和 yptr 分别存放在通用寄存器EDI、RSI和RDX中 参数 x 和 y 分别存放在XMM0和XMM1中 返回结果存放在XMM0中

在pirnt(\%d\n",a);的时候，第一个参数是FMT，第二个参数本来是a（是一个浮点数），应该要从XMM里面读取，但是写的是%d，所以从通用寄存器读取，而非XMM里面读取。

第二讲：复杂数据类型的分配和访问

一、 数组 (Arrays)

1. 内存分配

  • 全局/静态数组 (如 int global_arr[10];):
    • 位置: 编译时确定地址，存放在 数据段 (.data 或 .bss 区)。
    • 生命周期: 整个程序运行期间。
  • 局部数组 (如函数内的 int local_arr[10];):
    • 位置: 函数调用时在 栈 (Stack) 上分配。
    • 分配方式: 通过移动栈顶指针实现，如 subl $40, %esp。
    • 基地址: 通过栈帧指针 %ebp 的负偏移量来定位，如 -40(%ebp)。

2. 访问方式：基址 + 变址

数组访问的核心公式是：地址(arr[i]) = 数组基地址 + i * sizeof(元素类型)。

二、结构体 (Structs)

1. 内存分配
与数组类似，全局或静态结构体分配在数据段，局部结构体分配在栈上。

2. 数据对齐（Data Alignment）

  • 原因：为提升 CPU 访存效率，编译器会确保每个成员的起始地址是其自身大小的整数倍。
  • 行为：在成员之间自动插入填充字节（padding）。
  • 结果：sizeof(struct) 不一定等于各成员大小之和。
  • 示例：struct { char c; int i; };
    • c 位于偏移量 0（占 1 字节）；
    • 编译器填充 3 字节，使 i 的地址为 4 的倍数；
    • i 位于偏移量 4（占 4 字节）；
    • 总大小为 8 字节，而非 5 字节。

3. 访问方式：基址 + 偏移量
结构体成员的地址计算公式为：
地址(st.member) = 结构体基地址 + member 的偏移量(offset)。
其中，offset 在编译时确定。

  • 示例（struct Point { int x; int y; }）：
    • x 的偏移量为 0，y 的偏移量为 4；
    • 假设局部变量 p 的基地址为 -8(%ebp)；
    • 访问 p.x：movl $10, -8(%ebp)（基地址 + 偏移量 0）；
    • 访问 p.y：movl $20, -4(%ebp)（基地址 + 偏移量 4）。

4. 作为函数参数

  • 按值传递（不推荐）：

    • 过程：整个结构体被复制到栈上作为参数；
    • 缺点：
      1. 开销大：结构体越大，复制所需时间和栈空间越多；
      2. 无法修改：函数内修改的是副本，不影响原始数据。

  • 按地址/指针传递（强烈推荐）：

    • 过程：仅将指向结构体的指针（IA32 下为 4 字节）压入栈；

    • 优点：

      1. 开销小：无论结构体多大，传递的只是一个指针；
      2. 可修改：函数通过指针可直接修改原始数据。

    • 汇编对比：

      • 调用 func(p)：需将 p 的所有成员逐个 push 到栈；
      • 调用 func_ptr(&p)：只需计算 p 的地址并压栈：

联合体的分配与访问
联合体的所有成员共享同一块存储空间，其总大小等于所需空间最大的成员的大小。

数据对齐 1. 为什么需要对齐？ (The Why)

  • 硬件限制: 内存控制器通常按固定大小的块（如2, 4, 8, 16字节）读取数据。这个大小由内存总线宽度决定。
  • 性能考量: 如果一个数据（如4字节的int）被存放在一个内存块的内部（如地址8-11），那么一次内存访问就能读完。如果它跨越了两个块（如地址6-9），就需要两次内存访问和额外的拼接操作，效率极低。数据对齐就是为了避免这种情况。 2. 默认的结构体对齐规则 编译器为了保证性能，会遵循一套默认的对齐规则。这套规则可以总结为三条黄金法则： 法则1：成员对齐
    结构体中的每个成员，其起始地址相对于结构体起始地址的偏移量 (offset)，必须是该成员自身大小的整数倍。如果不是，编译器会在前一个成员后面填充字节（Padding）来凑齐。 法则2：整体对齐
    结构体作为一个整体，它的对齐字节数等于其所有成员中最大那个成员的大小。这个也叫作结构体的 alignment。 法则3：末尾对齐
    结构体的总大小必须是其整体对齐字节数（由法则2得出）的整数倍。如果不是，编译器会在最后一 例子：

3.手动控制对齐 #pragma pack(n): 数据紧缩 作用: 设置成员的最大对齐字节数。成员实际对齐按 min(自身大小, n) 计算。 常见用法: #pragma pack(1)，表示所有成员都按1字节对齐，即取消所有对齐填充。 attribute((aligned(n))): 提升对齐 (GCC/Clang) 作用: 强制一个变量或结构体类型的起始地址至少按 n 字节对齐。n 必须是2的幂。
