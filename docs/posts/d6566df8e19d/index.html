一、实验目的

本次实验的主要目标是综合运用多种渗透测试技术，最终获取目标靶机（demo2）的root权限。 为达成此目标，实验中依次使用了以下攻击技术：

  1. 主机发现：使用ARP扫描（arp-scan）发现局域网内的存活主机。
  2. 端口与服务扫描：使用Nmap对目标主机进行全面的信息收集。
  3. Web漏洞利用：
    • SQL注入：通过构造万能密码("admin ’ 1 and 1=1 # ")绕过网站登录认证。
    • 命令注入：利用Web应用后端存在的漏洞执行任意系统命令。
  4. 反弹Shell建立：通过命令注入漏洞，建立从靶机到攻击机的反向TCP连接，获取交互式Shell。
  5. 后渗透信息收集：在获得低权限Shell后，审计Web源码，发现硬编码凭证。
  6. 本地提权：在获得靶机的低权限Shell后，尝试利用多个系统内核漏洞进行权限提升，最终获取root权限。

从代码中得知，数据库用户名为john，密码为hiroshima。我基于这个发现进行了两次尝试：

  1. 尝试登录数据库：我试图使用mysql客户端连接本地数据库，但在输入mysql命令后，终端就卡死了，没有任何响应，也无法输入后续的用户名和密码。此路不通。
  2. 尝试复用凭证：我猜测这组凭证可能被复用于系统账户。但无论是尝试su john切换用户，还是通过SSH使用john:hiroshima登录，均提示密码错误。 由于这些尝试都失败了，我决定将重点转向内核提权。 4. 本地提权 首先，我查看了系统的发行版信息，确定目标系统为CentOS release 4.5 (Final)。

三、实验结果

本次实验最终成功完成。通过一系列的探索、尝试和纠错，我成功地从外部信息收集开始，逐步渗透，最终获取了目标靶机的最高权限——root权限。 总结实验成果如下：

  1. 成功利用SQL注入和命令注入漏洞，获得了靶机的初始访问权限。
  2. 在后渗透阶段发现了硬编码凭证，但利用该凭证的尝试未能成功。
  3. 尝试了两种不同的内核提权漏洞，其中35370.c失败，9542.c成功。
  4. 最终利用9542.c漏洞，将低权限的Web服务用户提升为root用户。 最终提权成功的截图如下：

四、实验中遇到的问题及解决方案

1. 虚拟机故障 实验进行到一半时，原靶机虚拟机出现故障(说什么显示器错误，只有shell界面，没有gui界面），无法继续操作。我重新建立了一个kali虚拟机，还是使用之前的vdi磁盘启动，直接从以前的内容开始做。 2. 提权漏洞编译失败 尝试编译35370.c提权脚本时，因缺少库链接而报错。通过查询资料，了解到需要链接pthread库，使用gcc 35370.c -o b.out -lpthread命令成功编译。 3. 提权漏洞执行失败 编译成功的35370.c在执行后，并未返回root Shell，反而导致整个反弹Shell会话卡死。这表明该漏洞利用程序可能不适用于当前系统的特定内核版本或环境。我没有继续在此问题上纠结，而是果断放弃该路径，转而尝试另一个更匹配的漏洞利用程序（9542.c），并最终取得成功。

五、实验启示与建议

本次实验过程曲折但收获颇丰，让我对渗透测试的真实场景有了更深的理解。 启示与收获：

  1. 实验中充满了尝试、失败和再尝试。无论是利用硬编码凭证的失败，还是第一个提权漏洞的失效，都说明了真实世界的攻击路径并非一帆风顺，需要不断调整策略。
  2. 当一条路走不通时，不能轻易放弃，而是应该回到信息收集阶段，寻找新的攻击向量。正是因为没有在失败的尝试上止步，才最终找到了成功的提权方法。
  3. 并非所有声称适用于某个版本的漏洞利用都能成功。环境的细微差别（如内核的具体编译选项）都可能导致利用失败。选择与目标环境最匹配的漏洞是提高成功率的关键。
