网络攻防实战实验报告

Lab5 靶机4

学生:   雷业成 (241220106)

南京大学计算机科学与技术系

一、实验目的

  1. 核心目标： 获取目标靶机billu b0x的root权限。
  2. 技术实践：
    • 主机发现 (arp-scan),端口扫描与服务识别 (nmap)
    • Web目录枚举 (dirsearch), SQL注入漏洞利用
    • 本地文件包含 (LFI) 漏洞利用, 文件上传漏洞绕过 (Magic Number修改),反向Shell获取,Linux内核漏洞提权

二、实验内容

本次实验的整体思路是，首先通过信息收集确定靶机的基本情况，然后重点对开放的Web服务进行深入挖掘，通过漏洞组合拳获取一个低权限的Shell，最后利用内核漏洞完成提权，获得root权限。

1. 信息收集

首先，使用arp-scan -l命令进行主机发现，确定靶机的IP地址为192.168.50.10。 随后，使用nmap对目标主机进行端口扫描，发现其开放了22 (SSH) 和80 (HTTP) 端口。这表明我们可以从Web服务入手。 为了解Web应用的结构，我使用了dirsearch工具对80端口进行目录扫描，发现了多个可访问的路径，其中/test、/phpmy/等路径引起了我的注意，这些可能成为后续的突破口。扫描结果部分如下：

2. Web渗透与漏洞利用 (思路一)

访问靶机Web主页，发现是一个登录界面。我首先尝试了常见的SQL注入Payload，并使用Burp Suite的Intruder模块配合Cluster Bomb攻击模式进行爆破，但均以失败告终。 (这里使用的是payloadbox/sql-injection-payload-list: 🎯 SQL Injection Payload List 这里的payload进行攻击，但是失败了） 在SQL注入陷入僵局时，我想起了目录扫描发现的/test路径。直接访问该路径，页面提示“file’ parameter is empty”。

我猜测这里可能存在一个文件包含漏洞，并且需要使用POST方法提交参数。通过Burp Suite将请求方法改为POST并添加file参数后，成功读取了文件内容。

利用这个文件包含漏洞，可以直接读取网站首页index.php的源码：

源码审计发现，后端代码使用str_replace('\'','',...)函数过滤了单引号，但并未过滤反斜杠\。因此，可以通过构造特殊的Payload来绕过验证。使用构造的Payload如下：

  • Username: or 1=1 #
  • Password: \ 这样，后端的SQL查询语句拼接后就变成了select * from auth where pass='\' and uname='or 1=1 #'，反斜杠\转义了第二个单引号，#注释掉了后面的内容，or 1=1条件永远为真，从而成功绕过登录验证。
2.2 文件上传绕过与反向Shell

成功登录后，进入了一个后台面板panel.php，该面板提供文件上传功能。 我首先尝试上传一个PHP一句话木马，但上传失败，说明后端存在文件类型校验。我猜测校验机制可能是基于文件头（Magic Number）。 之后，我用burpsuite进行抓包：

于是，我将一句话木马的文件改为png后缀，然后在burpsuite的repeater 木块中放行的时候在前面加上Magic numerGIF89a，以此来欺骗后端校验。

上传成功后，需要找到一种方法来执行这个被当作图片上传的PHP代码。我使用Burp Suite拦截了后台面板的请求（前面的抓包结果），发现在点击“continue”按钮时，会发送一个load=show&continue=continue的POST请求。联想到之前目录扫描发现的/show路径，我猜测load参数的值可能被用作文件名，并被包含执行。

我将load参数的值修改为上传后图片的路径，页面返回了乱码，这证实了我的猜想——服务器确实包含了该文件并尝试执行它。 随后，我准备了一个功能更完整的PHP反向Shell脚本（位于Kali的/usr/share/webshells/php/php-reverse-shell.php），修改了其中的监听IP和端口，cp为png文件，然后用 burp抓包加上MagicNumer。 在Kali上使用nc开启监听后，再次利用panel.php的文件包含I漏洞，将load参数的值设置为上传的反向Shell图片的路径。 发送请求后，nc成功接收到了靶机的反向Shell，此时获得了www-data用户的权限。

3. 提权

获取低权限Shell后，下一步是提权。我执行uname -a命令查看内核版本，输出显示内核版本为3.13。这是一个相对老旧的版本，可能存在已知的提权漏洞。 使用searchsploit工具搜索Linux Kernel 3.13的相关漏洞。 尝试了多个漏洞之后，并且失败之后，我发现了一个编号为37292的本地提权漏洞。

我查看了该漏洞利用脚本（37292.c）的内容，其中包含了详细的编译和执行指令。随后，我将该C文件上传到靶机的可写目录（如/tmp），使用gcc进行编译，并运行生成的可执行文件，成功获取了root权限。

[!?] 课上提问：如果靶机上没有gcc环境呢？ 我的想法：如果靶机上没有gcc环境，那么可能需要自己在kali上编译代码，并把编译好的可执行程序上传到靶机上，在靶机上运行。（但是可能架构不同？有需要交叉编译来在kali上编译出能在靶机上运行的程序）

4. Web渗透 (思路二)

在复盘时，我探索了另一条攻击路径。之前利用/test的LFI漏洞读取了index.php，我同样可以用它来读取其他敏感文件。当我尝试读取c.php时，成功获取了数据库的配置文件。 c.php文件内容暴露了数据库的用户名和密码。利用这组凭证，我成功登录了之前目录扫描发现的/phpmy/路径，这是一个phpMyAdmin管理界面。 在数据库中，我找到了auth表，其中存放着Web应用的登录用户名和密码。

获取这组凭证后，就可以正常登录Web后台，从而回到思路一中的文件上传步骤，继续后续的攻击。

注

在phpmyadmin界面，我尝试了这里其中的一些方法，但是都没有成功，因此最后是放弃了这个想法 PhpMyAdmin漏洞利用汇总 - 只言 - 博客园

三、实验结果

本次实验成功完成了预定目标。通过综合利用Web应用的SQL注入、文件上传绕过、本地文件包含等多个漏洞，成功获取了靶机的www-data用户Shell。随后，通过搜索并利用已知的Linux内核提权漏洞（exploit-db 37292），最终将权限提升至root，完全控制了目标靶机。

四、实验中遇到的问题及解决方案

  1. 问题： 初期的SQL注入尝试（包括自动化工具爆破）均失败。 解决方案： 没有放弃，而是转向利用目录扫描发现的文件包含漏洞。通过读取index.php源码，分析了其SQL查询的过滤机制，从而构造出password=\和username=or 1=1 #的精准Payload，成功绕过了登录验证。
  2. 问题： 上传了一句话木马后，使用AntSword等工具无法成功连接。 解决方案： 放弃了简单的一句话木马，改用Kali自带的功能更稳定、更完整的php-reverse-shell.php脚本。该脚本直接建立反向TCP连接，比WebShell管理工具更为可靠和直接。
  3. 问题（思考）： 如果靶机上没有gcc编译环境，如何进行提权？ 解决方案（设想）： 如果目标环境没有编译器，可以在攻击机（Kali）上进行交叉编译。需要确定目标靶机的系统架构（如x86_64），然后在Kali上安装相应的交叉编译工具链，将37292.c编译成适用于目标架构的可执行文件，最后再将编译好的二进制文件上传到靶机执行。

五、实验启示与建议

  1. 收集信息：详尽的目录扫描为后续发现文件包含漏洞提供了关键线索，如果忽略了/test和/phpmy/等路径，攻击可能无法顺利进行。
  2. 读源码 获取源码并进行人工审计，发现了str_replace函数的过滤缺陷，这是绕过SQL注入的关键。永远不要完全依赖工具。
  3. 多条路径通罗马： 实验中的“思路二”表明，达成目标往往不止一种方法。

附录：耗时统计

本次实验总耗时约5小时，其中：

  • 学习相关知识（SQL注入绕过、LFI、内核提权原理）：约1小时
  • 实施渗透实验（信息收集、漏洞利用、提权）：约3小时
