发表于2025-10-08|更新于2025-10-12|NJUCS网络攻防实战

注：完成实验的过程中，我尝试了课上讲的不同方法

一、实验目的

本次实验的目标是对一台提供 Apache 服务的靶机进行渗透测试，最终获取 root 权限。
整个过程包括网络信息收集、端口与服务探测、Web 页面分析、漏洞利用、反弹 shell、文件传输以及提权等完整的攻击链。
实验重点是综合利用信息收集与漏洞利用技术，掌握从枚举到提权的完整流程。

二、实验环境

  • 攻击机：Kali Linux
  • 靶机：demo 1.ova（NATNetwork 模式）
  • 工具：arp-scan、nmap、dirbuster、searchsploit、gcc、nc、python3 http.server、ssh、rockyou.txt 等

三、实验过程与思路

1. 网段扫描与端口探测

首先确定靶机在的网段，我使用 arp-scan -l扫描网段 10.0.2.0/24，后来发现是默认的NATNetwork网络无法上外网，在使用serachsopolit的过程中需要联机外网，因此新建了NatNetwork，网段改为了 192.168.50.0/24。

不过这里的 manual 貌似是 Apache 自带的文档，没有发现敏感信息。找来找去也不过是一些语法之类的东西。

四、实验结果

经过多轮扫描与利用，我成功取得了靶机的 root 权限，验证了漏洞利用与反弹 shell、提权流程。
整个实验过程包括了网络扫描、信息枚举、漏洞搜索、编译调试、利用与反弹 shell 的完整链条。

最终结果如下：

  • 成功获取 shell 并提权为 root
  • 通过 SSH 成功登录

五、实验中遇到的问题与解决方法

问题 解决方法
Kali无法上网 重新弄了一个NatNetWork
exploit 编译出错 问ai，然后安装 libssl-dev，添加 -lcrypto
exploit运行失败 自建 HTTP 服务让靶机下载缺少的文件
SSH 登录失败 问ai，调整 HostKeyAlgorithms 和 Ciphers 参数
没有解决的问题
  1. 我在获取了主机的一个用户名harold之后，最终还是没能爆破ssh进行登录
  2. 图中的两个Natnetwork只在网段上面有差异，但是却只有我自己的这个net是可以上外网的？

六、实验总结与启示

这次实验花了我大约六个多小时（不含学习时间，这个貌似没法量化？在做的时候也是边做边学），从晚上七点做到凌晨十二点半，外加上我实验报告一个小时。
主要是，上课的时候没有基础听不懂，然后课后只能自己琢磨

上课的时候由于自己环境问题和老师上课的内容不能同步，不过现在对于virtualbox比较熟悉了，吐槽一下，virtualbox的设置真的很反人类。。

其中大多时间是花费在了查找漏洞。我一共尝试了3个漏洞，在实验报告里面记录了有进展的两个，但恰恰是成功的那个花费了最少的时间。 完成实验报告又花费了我一个小时。

我一开始卡在网络不通的问题上，后来又在 exploit 编译、文件下载失败、SSH 登录兼容性这些小细节上浪费了大量时间。

此外，我对于kali上面的词典也不是很熟悉，每一次需要爆破的时候，都得去研究研究有哪些词典。

启示：主要还是对工具和渗透测试的流程不熟悉

意见： 个人相当不喜欢virtualbox，我觉得可以简单讲一下virtualbox的网络配置，主要是不理解各种配置的功能究竟是什么，导致陷入：有问题->删了重下->花时间捣鼓->没有结果->遇见新的问题。
