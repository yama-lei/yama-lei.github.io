一、实验目的

本次实验的主要目标是综合运用多种渗透测试技术，获取目标靶机（IP: 192.168.50.9）的最高控制权限，即root权限。 为达成此目标，实验中采用了以下攻击技术：

  1. 主机发现与端口扫描：使用arp-scan和nmap对目标进行信息收集。
  2. Web渗透：
    • SQL注入：绕过Web应用身份验证。
    • 命令注入：在Web应用后端执行任意系统命令。
  3. 初始访问：利用nc（netcat）串联建立反弹Shell，获取靶机的初步控制权。
  4. 权限提升：通过分析和利用目标系统上存在的SUID（Set User ID）程序漏洞，将权限从普通用户提升至root用户。

二、实验内容

1. 信息收集

首先，我使用arp-scan工具扫描本地网络，确定了靶机IP地址为192.168.50.9。随后，我使用Nmap对该主机进行详细的端口和服务扫描，命令如下：

扫描结果显示，目标主机开放了两个端口：22端口（OpenSSH 7.6p1）和8080端口（Werkzeug httpd 0.14.1，一个基于Python的Web服务）。

2. Web渗透与漏洞利用

我通过浏览器访问了http://192.168.50.9:8080，发现这是一个需要输入验证码的Web页面，如下图所示。

我推测验证码功能可能存在漏洞，于是使用Burp Suite对登录请求进行抓包分析。我将抓到的请求发送到Intruder模块，并加载了一个常见的SQL注入Payload字典进行模糊测试。 测试结果显示，部分Payload返回了与其他请求不同长度的响应，且状态码为500 (Internal Server Error)。查看这些响应的详细信息，发现页面返回了SQL语法错误，这表明后端存在SQL注入漏洞。

根据错误信息，我构造了1"or 1=1--作为Payload，成功绕过了验证，进入了Web应用的主功能界面——一个病毒扫描页面。

我推测该“扫描”功能是通过在后端执行系统命令实现的，因此可能存在命令注入漏洞。我在文件名后使用分号;拼接了ls命令进行测试。

页面成功返回了当前目录下的文件列表，证实了命令注入漏洞的存在。

3. 获取初始Shell

为了获得一个交互式的Shell，我决定利用命令注入漏洞建立一个反弹Shell。我在我的攻击机（IP: 192.168.50.8）上开启了两个nc监听端口，一个用于接收输入（3333端口），另一个用于回显输出（4444端口）。

  • 攻击机监听命令1：nc -nvlp 3333

4. 尝试提权

在获得初始Shell后，我开始进行本地信息收集以寻找提权机会。我尝试启动Python的SimpleHTTPServer将一些可疑文件下载到本地进行分析，例如一个数据库文件。但分析后发现其中只有一些用户名和邀请码，利用这些信息进行暴力破解也未能成功。

于是我转换思路，开始寻找系统上是否存在配置不当的SUID文件。在根目录下，我发现了一个名为update_cloudav.c的C语言源文件。

我检查了其编译后的二进制文件update_cloudav的权限，发现它设置了SUID位，并且所有者为root。这意味着当我执行这个程序时，将暂时获得root权限。 随后，我查看了update_cloudav.c的源代码，发现了一个严重的安全漏洞：程序直接使用了system()函数来执行从命令行传入的第一个参数，且未进行任何过滤。 然后我在我的攻击机上再次开启两个nc监听端口（3334和4445），然后将获取反弹Shell的命令作为参数传递给update_cloudav程序来执行。

  • 攻击机监听命令1：nc -nvlp 3334

命令执行后，我在攻击机的监听窗口收到了一个新的Shell，提示符为#，whoami命令返回root，表明提权成功。

三、实验结果

在实验中完成了设定的任务。通过一系列连贯的攻击步骤，我从外部信息收集开始，逐步渗透进入系统内部，最终通过利用配置不当的SUID程序漏洞，成功获取了目标靶机的root权限。实验的主要成果包括：

  1. 成功利用SQL注入绕过Web身份验证。
  2. 通过命令注入漏洞在目标系统上实现任意代码执行。
  3. 成功建立reverse shell，获得了对靶机的初始访问权限。
  4. 成功利用SUID提权漏洞，将权限从普通用户提升至root。

四、实验中遇到的问题及解决方案

问题： 在获得初始Shell后，最初的提权思路（分析数据库文件、尝试暴力破解SSH）未能取得进展。下载的数据库文件信息价值有限，直接浪费了一些时间。 解决方案： 当一条渗透路径进入死胡同时，我及时调整了策略。我放弃了在数据库信息上花费更多时间，转而开始寻找其他常见的Linux提权向量，例如查找系统中具有SUID/SGID权限的特殊文件。这种策略的转变是最终能够成功提权的关键。通过系统化的枚举和排查，我很快定位到了存在漏洞的update_cloudav程序，并找到了提权的突破口。

五、实验启示与建议

在一个路径走不通的时候，需要尝试多个方法，以及，方法不是一成不变的，根据情况灵活变通。
